Prompts, structure, APIs (pages 01–03)

1. In a ticket-analysis chain, which step should NOT use an LLM?
Exact work (count, sort, join) belongs in code: cheaper, exact and testable. See page 01.
2. Self-consistency means…
Low agreement between samples is also a useful signal to route a case to a human.
3. Schema-enforced structured output guarantees…
Shape, not truth. Domain validation in code is still required. See page 02.
4. A field (e.g. order ID) may be missing from the input. Best schema design?
Required-but-absent fields push the model to invent values.
5. Which HTTP status should your LLM client NOT retry?
401 needs a credential fix. Retry 408/409/429/5xx and network errors with jittered back-off. See page 03.
6. finish_reason == "length" means…
Treat it as an error for structured output. Raise the limit or shorten the task.
7. To benefit from prompt caching, you should put…
Caches typically match identical prefixes.

Tools, embeddings, RAG (pages 04–06)

8. In tool calling, the arguments field of a tool call is…
Treat it like HTTP parameters. See page 04.
9. Which tool design is best for an inventory assistant?
Specific, constrained tools. Keep reads and writes separate.
10. You switch to a new embedding model. What must you do?
Store the model version with each vector. See page 05.
11. Users search for exact codes like "CASE-RUGGED" and semantic search misses them. Best fix?
Keyword search excels at exact codes. RRF combines rankings without comparing raw scores.
12. Where should per-user document permissions be enforced in RAG?
If it's never retrieved, it can't leak. See page 06.
13. A good RAG prompt should include…
Then verify citations in code.

Agents, skills, MCP (pages 07–09)

14. In a test-first agent loop, what stops the agent "cheating"?
See page 07.
15. Migrating Scala 2.13 → 3: what should you use before asking an agent to edit by hand?
Deterministic tools first. Agents handle the judgement calls left over.
16. A skill rarely triggers. What do you change first?
Only name + description are visible up front. See page 08.
17. Why give each custom agent (planner, reviewer…) its own limited toolset?
Narrow roles plus artefact hand-offs keep contexts clean.
18. What does Metals MCP give an agent working on Scala code?
Real APIs instead of guesses. See page 09.

Testing, local models, data (pages 10–12)

19. A mutant "survived" in mutation testing. This means…
Feed survivors to AI to write tests from the spec. See page 10.
20. How should you evaluate AI-generated SQL against golden questions?
Different SQL can be equally correct. Execution accuracy is what matters. See page 12.
