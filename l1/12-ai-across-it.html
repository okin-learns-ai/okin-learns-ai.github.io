12 · AI Across IT: DevOps, QA, Data, Security and More

Coding is only part of IT work. AI helps across the whole software lifecycle: requirements, architecture, testing, operations, security, data, documentation and communication. This page is a tour of high-value uses in each area, with starter prompts and the cautions that matter.

AI across the software lifecycle

Requirements, planning & project management

  • Turn meeting notes into user stories with acceptance criteria.
  • Find gaps and contradictions in a spec. Generate edge cases.
  • Break an epic into tasks, flag dependencies and risks.
  • Draft status updates, release announcements, stakeholder emails.
Here are rough notes from a product meeting. Turn them into user stories in the format
"As a <role>, I want <goal>, so that <benefit>" with Given/When/Then acceptance criteria.
Then list ambiguities I must clarify with the product owner.
<notes>
CautionEstimates from AI are guesses. Use them to structure discussion, not to commit dates.

Architecture & design

  • Generate and compare design options with trade-off tables.
  • Draft Architecture Decision Records (ADRs).
  • Create diagrams as code (Mermaid, PlantUML, C4) from a description or from code.
  • "Pre-mortem": ask the AI how the design will fail in production.
Act as a principal engineer. Here is my proposed design for an event-driven order pipeline
(Kafka + Scala services). Run a pre-mortem: list the 10 most likely ways this fails in production
(ordering, duplicates, poison messages, back-pressure, schema evolution...), and for each the
mitigation. Then write an ADR draft for the final design.

QA & testing

  • Generate unit tests, property-based tests and parametrised cases.
  • Derive test cases from requirements (boundary values, equivalence classes).
  • Generate realistic, anonymised test data and fixtures.
  • Write end-to-end test scripts (e.g. Playwright) and explain flaky tests from logs.
  • Review a test suite for gaps: "which behaviours of this class are untested?"
Given this function and its existing tests, list behaviours that are NOT tested, ranked by risk.
Then write the 5 most valuable missing tests.

DevOps, CI/CD & infrastructure as code

  • Write and debug CI pipelines (GitHub Actions, GitLab CI, Jenkins) for sbt or uv projects.
  • Generate Dockerfiles, Kubernetes manifests, Helm charts, Terraform modules.
  • Explain cryptic build failures and dependency conflicts (sbt eviction warnings!).
  • Optimise pipelines: caching, parallelism, splitting test suites.
Write a GitHub Actions workflow for an sbt multi-module Scala 3 project: JDK 21, cache Coursier
and sbt, run scalafmtCheckAll, compile, test in parallel per module, and upload test reports.
Explain every step in comments.
High-risk area IaC and pipeline changes can delete infrastructure or leak secrets. Always run terraform plan / dry-runs and review them yourself. Never give agents production credentials. Check that AI-written pipelines don't print secrets to logs.

SRE, operations & incident response

  • Summarise huge logs and find the first error and its probable cause.
  • Explain stack traces, GC logs, thread dumps (JVM!) and heap histograms.
  • Draft runbooks from past incidents. Write blameless postmortems from timelines.
  • Write queries for observability tools (PromQL, LogQL, SQL over logs) from plain English.
Here is a JVM thread dump from a Scala service that stopped responding. Identify deadlocks,
thread-pool starvation (esp. blocking on a compute pool), and the threads most likely responsible.
Explain in plain language and suggest the fix.
<thread dump>
CautionLogs often contain personal data, tokens and internal hostnames. Redact them, or use an approved internal or local model.

Data engineering & analytics

  • Write and optimise SQL. Explain query plans.
  • Generate Spark jobs (Scala or PySpark) and explain physical plans.
  • Design schemas and migrations. Generate data-quality checks.
  • Exploratory analysis in notebooks: profiling, charts, anomaly spotting.
  • Translate business questions into metrics definitions.
Schema below (Postgres). Write a SQL query for monthly active customers per region for the last
12 months, where "active" = at least one paid order. Explain the query, then list assumptions
I should verify (time zones, refunds, test accounts).
<schema>
Always validate generated SQLCheck results on a small sample where you know the answer. Text-to-SQL is often almost right: a missing filter, a wrong join type, double counting.

Security (DevSecOps)

  • Explain vulnerabilities (CVEs) in plain language and whether your usage is affected.
  • Review code for injection, authz gaps, unsafe deserialisation, secrets in code.
  • Draft threat models (STRIDE) for a feature.
  • Triage scanner output: separate real issues from noise.
  • Write secure defaults: CSP headers, input validation, least-privilege IAM policies.
Create a STRIDE threat model for this feature: users upload CSV files that are parsed by a
Scala service and stored in S3, with results shown in a web UI. Output a table:
threat, STRIDE category, likelihood, impact, mitigation.
CautionAI review is an extra layer and does not replace security tooling (SAST/DAST/dependency scanning) or expert review for sensitive systems.

Documentation & communication

  • Generate READMEs, API docs, onboarding guides, and docs from code.
  • Keep docs in sync: "Here is the diff. Which parts of the docs are now outdated?"
  • Rewrite for different audiences: executive summary, engineer details, customer notes.
  • Improve clarity and tone of emails, PR descriptions and design docs.
  • Translate documentation between human languages.

Frontend, UI & accessibility

  • Turn screenshots or sketches into UI code. Multimodal models read images.
  • Check accessibility: missing labels, contrast, keyboard navigation, ARIA usage.
  • Generate component variations and design-system documentation.

Mobile & Apple platforms

  • Xcode's coding intelligence and agents build, test and search Apple documentation (page 06).
  • On-device AI in apps: Apple's Foundation Models framework gives Swift apps access to the on-device model for summarisation, extraction and generation, with privacy benefits. Core ML and MLX cover custom models.
  • AI helps with App Store copy, localisation and privacy-manifest explanations.

IT operations, support & sysadmin

  • Write and explain shell/PowerShell scripts, cron expressions, regexes, awk/jq one-liners.
  • Troubleshoot networking (DNS, TLS, proxies) from command output.
  • Draft knowledge-base articles from resolved tickets.
  • Classify and route support tickets (a classic LLM application, covered in Level 2).
Explain this command piece by piece, then tell me if it is safe to run:
find / -name "*.log" -mtime +7 -exec rm {} \;
Never run commands you don't understand Especially commands involving rm, chmod -R, dd, curl | sh, firewall rules or production databases. Ask the AI to explain and to propose a dry-run first.

Your career & soft skills

  • Rehearse interviews (system design, coding, behavioural) with feedback.
  • Prepare for difficult conversations: role-play the stakeholder.
  • Turn your work into a clear brag document or promotion case.
  • Learn new domains (finance, healthcare, logistics) fast enough to talk to experts. See page 13.

Key takeaways

  • AI adds value at every lifecycle stage: plan, design, build, test, review, deploy, operate, learn.
  • The best uses are explaining, drafting, generating options, summarising and translating.
  • Scale your verification to the risk. IaC, security, data and production need extra care.
  • Redact sensitive data and use approved tools.
