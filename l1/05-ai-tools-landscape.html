05 · The AI Tools Landscape

There are hundreds of AI tools, and new ones appear every week. Instead of memorising products, learn the categories and the layers they sit on. Then any new tool takes five minutes to place.

Level 135 minTrack 5 · ToolsLast verified 2026-10

By the end of this page you can

  • Place any AI tool into one of the layers of the AI stack.
  • Know the main categories: models, chat apps, IDE assistants, terminal agents, cloud agents, local runners, frameworks, data stores, evaluation tools and protocols.
  • Choose tools using sound criteria rather than hype.
About product names Product names below are examples to make categories concrete. This is not an endorsement or a complete list. Features and names change often, so check each tool's current docs. Your company may also have an approved list. Follow it.

Model hubs such as Hugging Face host hundreds of thousands of open models, datasets and demos.

Chat assistants

General-purpose apps (web, desktop, mobile) for conversation, writing, analysis, research and learning. Typical features: file upload, web search, code execution/analysis, image understanding, "projects" with shared files, memory, and connectors (often via MCP).

Examples: ChatGPT, Claude, Gemini, Microsoft Copilot, Perplexity (search-first), NotebookLM (research over your own sources).

IDE assistants

AI built into the editor: completion, chat, inline edits and agent mode. Covered in depth on page 06.

TypeExamples (illustrative)
Built into the IDEXcode coding intelligence (with built-in model integrations and agents), JetBrains AI Assistant and the Junie agent (IntelliJ IDEA), Copilot Chat in VS Code

AI-first editorsEditors designed around AI agents, e.g. Cursor, Zed and others (often forks of VS Code)

Terminal (CLI) agents

Agents that run in your terminal. They read and edit files, run commands and tests, and use git. They work with any editor, and many integrate with IDEs and with each other through protocols.

Examples: Claude Code, OpenAI Codex CLI, Gemini CLI, GitHub Copilot CLI, Aider (open-source), OpenCode (open-source).

Cloud / background agents

Agents that run on remote machines. You hand them a task (often from an issue or chat), they work in a sandbox, and they come back with a pull request. Good for parallelising well-specified work.

Examples: GitHub Copilot coding agent, OpenAI Codex (cloud), and similar offerings from other vendors.

Local model runners

ToolWhat it does
OllamaSimple CLI/server to download and run open models locally with an OpenAI-compatible API.
LM StudioDesktop app to discover, run and chat with local models. Exposes a local API server.
llama.cppThe high-performance C/C++ engine underneath many local tools (GGUF format).
MLXApple's open-source array framework for machine learning on Apple silicon. Runs and fine-tunes models efficiently on Macs.
vLLM / TGIHigh-throughput servers for hosting models on GPUs (Level 4).
When local makes sense Sensitive data that must not leave the machine, offline work, experiments, cost control, or learning how models behave. Local models are usually less capable than frontier hosted models, so match the model to the task.

Frameworks are optional Many experienced teams call model APIs directly and add a framework only when it clearly saves effort. Learn the raw API first (Level 2). Then you will understand what any framework is doing for you.

Data: vector databases & search

Store embeddings and search by similarity. This is the backbone of RAG.

Examples: pgvector (Postgres extension), Qdrant, Weaviate, Milvus, Chroma, Pinecone, and vector search in Elasticsearch/OpenSearch, Redis and cloud databases.

Evaluation & observability

Measure quality, trace agent runs, track cost and catch regressions (Level 3).

Examples: promptfoo, Langfuse, LangSmith, Arize Phoenix, Weights & Biases, and OpenTelemetry's semantic conventions for GenAI.

How to choose a tool

CriterionQuestions to ask
Policy & privacyIs it approved by my organisation? Where does my code go? Is data used for training? Is there an enterprise or zero-retention option?
Fit to stackDoes it support my IDE (IntelliJ for Scala, Xcode for Swift, VS Code)? Does it understand my build tool (sbt, Mill, Gradle)?
Model choiceCan I pick models? Bring my own key? Use local models?
Agent capabilitiesCan it run tests and commands? Is there a permission model? Does it support MCP, skills and AGENTS.md?
Quality on your codeTry the same 3 real tasks in each candidate. Benchmarks don't predict your codebase.
CostSeat price vs usage-based pricing. Limits on premium models.
Lock-inAre configs in open formats (AGENTS.md, SKILL.md, MCP) that I can carry to another tool?
Expert habit: a personal benchmark Keep 5–10 real tasks from your own work (a tricky Scala type error, a Spark optimisation, a refactor, a test suite to write). When a new tool or model appears, run your benchmark. In 30 minutes you will know more than any review could tell you.

Key takeaways

  • Think in layers: infrastructure → models → frameworks → protocols → customisation → experiences.
  • The main categories are chat apps, IDE assistants, terminal agents, cloud agents, local runners, frameworks, vector DBs, evals and protocols.
  • Open standards (MCP, AGENTS.md, Agent Skills) make your setup portable between tools.
  • Choose with policy, fit, quality on your own tasks, cost and lock-in in mind.
